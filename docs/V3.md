# Outpost V3 connectivity

The terminal supports paired, direct-only and server-managed machines.
[Architecture](ARCHITECTURE.md) describes the current implementation.

## Goal

Every coding agent on every machine Outpost can reach works with every other
one: it can find it, message it, share files with it, and search what any of
them did before. You reach all of them from a browser or Outpost Desktop, and
what Outpost shows matches what the coding tool is actually doing.

### How a client reaches a managed session

The terminal client always requests the attachment. Once established, the
session can send output, events, images and files on that same bidirectional
connection. The client needs no listening port. A desktop local shell is a
separate feature.

| Situation | Who opens each network connection | Where session traffic goes |
| --- | --- | --- |
| The client can reach the target | Client opens a connection to the authenticated target endpoint | Directly between client and target |
| The client cannot reach the target | Client opens a connection to Outpost. The target maintains an outbound connection to the same Outpost deployment | Outpost joins the two connections for this attachment |
| The direct endpoint is unreachable and the target has no connection to the relay | No usable route | Report the target offline and keep its session alive |

**Direct-only policy.** A restricted host imports its owner’s public key offline.
Clients obtain signed grants from that deployment and reach the target endpoint
themselves. The target cannot fall back to a relay. Linux installations bind one
server and execution account until explicitly released. See [machine ownership
and direct-only setup](ARCHITECTURE.md#installing-and-removing-a-machine).

**Pairing and discovery.** A target owner pairs the target with one deployment.
The target authenticates its outbound relay connection using its target identity.
Outpost records the connection against the owner and target. The target can also
advertise an explicitly configured direct endpoint, such as a LAN or VPN address.
An outbound relay connection is sufficient on a private network. Enrollment
has to work on the target itself when the server cannot SSH to it.

**Attach.** The signed-in client requests an attachment for a target and session.
Outpost authorizes that exact tuple and returns available routes. The client
gives the direct route a bounded head start and authenticates the target before
sending session credentials. If the direct route cannot be established promptly,
it can try the relay. Route probes have no PTY side effects. Exactly one winning
route commits the attachment. Denied access or an ended session is definitive
across routes. A relay route failure and a target authentication failure must be
distinguishable in diagnostics.

**Transfer.** Terminal input and output, file publication notices, file listing,
file reads and image paste share the selected attachment. File content travels
in bounded chunks with flow control and cancellation. Control messages and PTY
traffic have priority over queued bulk data. When an agent publishes a file, the
target sends its metadata to attached clients. A client can request its bytes
over the connection it already opened. The target keeps the published file for
clients that reconnect later.

**Reconnect.** The target owns the PTY and scrollback. The client tries the
available routes again after a disconnect and resumes the same session from
a checkpoint. It never automatically resends keystrokes, paste operations or a
request to start an exited tool. Partially downloaded files are discarded unless
their identity and offset can be verified. Keep a healthy relay attachment until
a reconnect; probing for a faster path must not start a second PTY.

**Authority.** Relaying is scoped to an enrolled target and an authorized session.
A client cannot name an arbitrary network destination or open a machine management
stream with an attachment ticket. Direct tickets are audience-bound to the target.
The relay authenticates both sides and cancels active attachments when their
authority is revoked. Diagnostics expose the selected route and reason for
fallback, while keeping credentials out of logs.

**Control plane and data plane.** The public Outpost origin owns account sign-in,
the machine directory, pairing and revocation. A direct connection can still
consult this origin for an attachment grant. Its PTY and file bytes go directly
to the target. On the relay path, the server opens a session stream inside the
already registered machine connection. That logical open is what changes on a
private target: calling the existing SSH launcher on a relay miss would
reintroduce the inbound-network dependency.

A direct endpoint has to work for the requesting client. For the browser this
includes a TLS identity the browser accepts and applicable local-network
permissions. A paired endpoint must also prove possession of its single-use route secret.
Only target-advertised addresses belong in the route list. A failed probe must
not disclose account credentials, consume a single-use launch ticket or grant
access to a different host after a redirect.

**Running V3.** A paired machine uses `outpost-terminal pair` for enrollment and
`outpost-terminal connect` for its outbound link. Both routes require the
deployment for authorization and revocation. The direct route is available when
a paired target advertises its HTTPS endpoint. SSH-managed targets continue to
use their server-managed path. See the [pairing and endpoint setup](ARCHITECTURE.md#connecting-a-paired-target).

**Acceptance criteria**

- On a reachable LAN or VPN, a direct attachment carries terminal traffic and
  a file in each direction. The relay carries zero session payload bytes.
- Block every new inbound connection to both client and target. With outbound
  access to the public relay, the client can attach, paste an image, and retrieve
  a published file. Verify the target makes no connection to the client.
- Make a direct endpoint slow, unreachable or present the wrong identity. Verify
  bounded fallback, credential isolation and exactly one active attachment.
- Interrupt a transfer or drop the active route. Verify that the session and
  its scrollback survive, another viewer stays connected, partial transfers
  release resources, and user input is applied at most once.
- Reject cross-account attachments, tickets presented to another target, and
  revoked enrollments on either route.

### Other scope

Managed sessions run on Linux, including WSL. Desktop local shells use native
PTYs. Agent-to-agent communication is scoped to the owning account.
